## 재현과 수정

- App 홈의 수동 새로고침은 같은 출처의 모든 캐시를 지우고 모든 서비스 워커 등록에 정리/업데이트 메시지를 보내고 있었다. SW의 `CLEAR_CACHE` 수신부도 모든 캐시를 지웠다.
- 이전 자동 갱신 등록 시험은 로드·가시성·온라인 복귀 경로만 다뤘으므로 수동 새로고침의 범위는 별도 확인이 필요했다.
- 실제 App의 새로고침 버튼 핸들러와 실제 SW 코드를 실행한 모의 환경 시험에서 `unrelated-cache` 삭제를 재현했다. 수정 전 새 시험 2개 실패, 기존 6개 통과. `.agy-work/257_pwa_red.log`.
- Gemini가 두 정리 경로에서 `voca-study-cache-` 접두사만 선택하도록 바꾸고, App은 정확히 이 앱의 `/` 스코프 등록만 업데이트하도록 바꿨다. SW는 v9로 갱신했다.
- 사용자 단어장/기록의 IndexedDB와 localStorage를 삭제하거나 초기화하는 동작은 추가하지 않았다. 다른 출처는 브라우저가 원래 격리한다. 이번 수정은 같은 출처에서 앱과 무관한 캐시·하위 스코프 등록을 보존하는 경계다.
