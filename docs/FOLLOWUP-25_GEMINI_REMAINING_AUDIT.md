## 1. 코드 기반 확인 완료 내역 (Code-Backed Checked Items)

1. **원문 표시 및 평가 페이로드 보존 (`CoachTutorController.ts`)**:
   - `normalizeRepeatAnswerKey`는 오직 컨트롤러 내부의 캐시 일치 판정용 키(`normalizedKey`) 비교에만 사용됩니다.
   - 사용자 화면에 표시되는 `recognizedText` 스냅샷과 실제 `deps.evaluate(questionId, answer)`로 전달되는 인자(`answer`)는 정규화되지 않은 순수 원본 텍스트를 그대로 유지합니다.
2. **의미 변경 유발 요소의 엄격한 재평가 분기**:
   - 내부 쉼표(`,`), 하이픈(`-`), 슬래시(`/`), 소수점(`.`), 아포스트로피(`'`)는 절대 제거되지 않으므로 의미가 바뀔 수 있는 발화는 반드시 실제 AI 평가를 거칩니다:
     - 축약형 vs 평서형: `I can't swim.` vs `I cant swim.`, `We're happy.` vs `Were happy.`, `We'll have tea.` vs `Well have tea.`
     - 단어 의미 구분: `re-sign` vs `resign`, `ice cream` vs `icecream`
     - 수치 구분: `2.8` vs `28`, `2,800` vs `2800`, `+2` vs `-2`
     - 부정 및 단어 변경: `not` 추가/누락, 이름/음료/나이 변경 (`Alex` vs `Alexa`, `coffee` vs `tea`)
3. **라이프사이클 및 오염 방지 경계**:
   - `start()` 호출 시(동일 질문 재시작 포함) `this.lastValidatedEntry = null;`로 즉시 초기화되어 첫 답변은 항상 AI 평가를 거칩니다.
   - `pause()` 호출 시 즉시 캐시가 제거되어 이전 세션의 응답이 다음 세션으로 넘어가지 않습니다.
   - `abort`된 비동기 평가 응답은 `!signal.aborted` 조건에 의해 캐시에 저장되지 않습니다.
4. **미완성·단답 및 음성 수집 실패 시 크레딧 부여 차단**:
   - 단답형(`sentenceComplete: false`), 오답(`needs_help`), 불확실(`uncertain`) 결과는 캐시 슬롯에 저장되지 않습니다.
   - 구두점 단독 입력(`...`, `?!`)으로 정규화 키가 빈 문자열이 되는 경우 캐시 슬롯 생성을 원천 차단합니다.
   - 중간(interim) 결과는 미리보기이며 재사용 크레딧을 주지 않습니다. 네트워크 에러(`network`) 등 수집 실패는 오류/중단 처리하며, 이전 정답으로 대체 통과하지 않습니다.

## 2. 잔여 자동화 테스트 제안 (최대 3개 유의미 후보)

현재 74개 파일 725개 테스트가 통과 상태이며, 중복 구현 검증이 아닌 실질적인 경계 케이스 보강을 위해 다음 3가지를 권고합니다:

1. **아포스트로피 및 문장부호 복합 조합 시 빈 키 방어 테스트**:
   - 예: `''''`, `'.'`, `'!?'` 등 아포스트로피와 종결부호만으로 구성된 입력이 들어왔을 때, `normalizeRepeatAnswerKey`가 안전하게 처리되어 잘못된 빈 키 일치로 통과되지 않는지 검증.
2. **긴 공백/탭/줄바꿈 혼합 발화의 텍스트 모드 재사용 안정성 테스트**:
   - 예: `\n\t  My   name \t is Alex.  \n` 형태로 텍스트 입력창에서 비정형 공백이 제출되었을 때 정상적으로 단일 공백으로 축약되어 재사용되는지 확인.
3. **반복 중 불확실(uncertain) 발화 발생 후 다시 기승인 정답 발화 시 복구 동작 테스트**:
   - 초기 발화(Alex 승인) $\rightarrow$ 1차 반복에서 불확실한 웅얼거림(Blorpt $\rightarrow$ paused) $\rightarrow$ 재시작 없이 텍스트/음성으로 다시 Alex를 발화했을 때의 캐시 유효성 유지 및 재사용 여부 확인.

### [필수 1] 음성 모드: 첫 질문(이름) 말하기 $\rightarrow$ 동일 발화 반복
1. "코칭 시작"을 누르고 영어 질문(`"What is your name?"`)을 끝까지 듣습니다.
2. 10초 마이크가 켜지면 말합니다:
   - 🗣️ **발화**: `"My name is Alex."`
3. 10초 수집과 최종 인식 확정 후 첫 번째는 AI 분석을 거쳐 한국어 피드백이 나옵니다. 응답 시간은 네트워크와 공급자 상태에 따라 달라집니다.
4. "따라 말해 볼까요?" 안내 후 마이크가 켜지면 **화면에 나온 문장 그대로** 똑같이 말합니다:
   - 🗣️ **발화**: `"My name is Alex."`
5. **확인할 점**:
   - 10초 듣기와 최종 인식 확정 후 추가 AI 분석 대기 없이 한국어 피드백을 거쳐 1/1 완료 및 "다음 질문으로" 버튼으로 진행하는지 확인합니다.

---

### [필수 2] 텍스트 모드: 대소문자 및 느낌표/마침표 표기 차이 확인 (결정론적 검증)
> 💡 음성 인식기는 사용자가 원하는 대소문자나 느낌표를 강제로 입력하기 어렵습니다. 표기 차이 재사용은 **텍스트 모드**에서 가장 확실하게 확인하실 수 있습니다.

1. 같은 학습 주소를 다시 열어 새 학습에서 **"텍스트 모드로 전환"** 버튼을 누릅니다.
2. "코칭 시작"을 누른 후, 첫 번째 답변을 입력하고 제출합니다:
   - ⌨️ **1차 제출**: `My name is Alex.` $\rightarrow$ **AI 분석 거침** (정상)
3. 따라 말하기 입력창이 나오면 **대문자와 느낌표**로 바꾸어 입력하고 제출합니다:
   - ⌨️ **2차 제출**: `MY NAME IS ALEX!` $\rightarrow$ **AI 분석 대기 없이 즉시 1/1 완료**
4. **확인할 점**:
   - 글자 케이스와 느낌표가 달라도 의미가 동일하므로 AI 재호출 없이 즉시 완료되는지 확인합니다.

### [필수 3] 변경된 답변 및 단답형 흐름 확인
1. **이름 변경 시 AI 재호출 확인**:
   - 새로 시작하여 1차에 `My name is Alex.`, 2차에 `My name is Mina.`를 말하거나 입력하면, 다른 이름이므로 **정상적으로 AI 분석을 거치고 화면에 Mina 피드백이 반영**되어야 합니다.
2. **세 번째 질문(카페) 단답형 2회 연습 확인**:
   - 질문(`"What would you like to drink?"`)에 `Coffee, please.` 단답 제출 $\rightarrow$ AI가 완전한 문장 권장하며 2회 연습으로 설정.
   - 첫 번째 따라하기: 실제 화면에 제시된 완전한 문장(예: `I'd like a coffee, please.`) $\rightarrow$ **AI 분석 거침**.
   - 두 번째 따라하기: 같은 문장(또는 허용한 표기 차이) $\rightarrow$ 최종 인식 확정 후 **추가 AI 분석 없이** 피드백을 거쳐 2/2 완료.

### ⚠️ 점검 시 주의 사항
- **모든 지연이 오류는 아닙니다**: 10초 음성 수집, 최종 인식 확정 및 음성 피드백 시간은 남습니다. 재사용은 추가 AI 요청과 그 응답 대기를 생략한다는 뜻이며 특정 시간 이내 완료를 보장하지 않습니다.
- **숫자 단어 vs 아라비아 숫자**: 음성 엔진이 `twenty eight`과 `28`처럼 단어/숫자 표기를 다르게 변환하거나, 축약형(`can't` vs `cant`)이 달라지면 의미 변경 위험을 방지하기 위해 정상적으로 새 AI 평가가 실행됩니다.

## 5. Codex 감독 검토 및 채택

- 반영: 새 통합시험으로 중간 결과 `MY NAME IS ALEX!` 후 최종 `My name is Mina.`가 AI 평가되는 것을 확인했다. 관련 5파일 109시험, 전체 74파일 726시험 PASS. 상세는 [Codex 확인·결과](FOLLOWUP-25_S25_CHECK_AND_RESULT.md).
- 미반영: 구두점 복합 입력의 비교 키 자체 시험은 실제 승인되지 않은 입력에 정답을 부여할 근거가 없고, 빈 키 차단/단답·불확실 캐시 금지 시험이 이미 있다. 긴 공백 조합은 기존 탭/연속 공백 및 텍스트 재사용 시험과 겹쳐 필수 누락으로 채택하지 않았다.
- 보류: uncertain 후 새 시작 없이 이전 정답으로 복구하는 흐름은 현재 중단/재시작 UX의 변경 여부를 먼저 정할 사항이다. 이번 검토에서 재현된 결함은 아니므로 임의 제품 변경을 하지 않았다. 새 시작·pause 시 정답 초기화 시험은 유지한다.
- 감사의 필수 2·3은 추가 점검이며 기본 음성 시험 뒤 선택해서 수행할 수 있다. 정상 화면의 진단 메뉴 표시, 응답 1~2초 보장, 즉시 완료로 오해할 표현을 Codex가 바로잡았다.
