## 요청과 범위

## 구현 목표

- 카페 주문의 음료 → 온도 → 크기 → 매장/포장 → 추가 옵션 → 결제 6문항. 음료 답변에 이미 온도를 제시하면 온도 질문을 생략하는 5문항 경로.
- 새 답변에 대한 의미·완성도·한국어 피드백·영어 예문·후속 질문 선택을 기존 단일 AI 호출로 처리한다. 서버 카탈로그의 허용 간선만 인정하며 마지막 결제에서만 종료한다.
- 최근 최대 2턴, 맥락 JSON 1,024 UTF-8 바이트, 요청 본문 4 KiB 제한. 새로운 동적 프롬프트 데이터도 16,384 기본 예약 위에 계량한다.
- 완전한 정답은 1회, 단답·교정은 2회 반복한다. 실제로 승인된 동일 문장 반복만 추가 호출 없이 처리한다. 예문·변경 답변·새 질문은 캐시 정답으로 자동 승격하지 않는다.
- 한국어 안내와 영어 질문, 10초 듣기, 인식 확인 대화 없음, 성인 확인 1회 저장, 반복 완료 후 사용자 ‘다음’ 선택을 유지한다.

## 실제 운영 API 1차 검증

제품 커밋 `9caa7f8`을 main에 푸시하고 기존 운영 루트에 반영했다. HTTP 200과 새 자산 `index-BTQnDXAG.js`를 확인했다. 합성 발화를 로컬 Controller에서 생성하고 실제 운영 API·Google 평가·운영 D1을 연결했다. 이 검증의 마이크·TTS는 모의이며 실제 음성 정확도 시험은 아니다.

- iced tea → 반복 중 iced coffee 변경 → 크기 → 포장 → 옵션 → 결제: **5문항 / 평가 6회**. 변경 답변은 다시 평가하고 최신 승인 문장을 후속 맥락에 반영했다.
- Coffee, please. → 완전한 문장 재평가 → 동일 반복 재사용 → 온도 → 크기 → 포장 → 옵션 → 결제: **6문항 / 평가 7회**. 초기 단답은 뜻을 인정하면서 2회 문장 연습으로 연결했다.
- 실제 HTTP/제공사 평가 **13회 모두 성공**, 일일 consumed **73 → 86건(+13)**, 예약 유닛 **1,207,464 → 1,428,521(+221,057)**. 클라우드 STT·TTS 기록 **0건 유지**. 승인된 동일 반복은 추가 차감이 없었다.
- 해당 13회 응답 시간: **1,245~2,003ms, 중앙값 1,436ms**. 이 표본은 합성 입력의 API 왕복 시간이며 S25 마이크 대기·TTS나 향후 항상 같은 속도를 보장하지 않는다.
- 360px 브라우저 폭에서 화면의 scrollWidth와 clientWidth가 같아 가로 넘침이 없었다.
