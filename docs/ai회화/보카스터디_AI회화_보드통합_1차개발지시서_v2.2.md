## 0. 수행 방식 — 회화 구현 + 보드 갱신을 쪼개지 말고 통합 완료

당신은 **구현 책임 AI(Codex)**다. 문서 검토만 하고 멈추지 말고, 이번 지시서의 허용 범위를 **하나의 통합 작업 패키지**로 처리하라. 순서는 **현행 조사 → 안전 기준 확보 → 설계 확정 → 코드 구현 → 실험·자동시험 → 발견한 결함 자체 수정 → 재시험 → 최종 보고**이다. 이미 통과한 영역에 대한 불필요한 재감사를 반복하거나, 자잘한 기능마다 사용자 승인을 받지 말라. 외부 계정·비밀키·기기·운영 권한이 없어 막히는 항목만 정확히 `NOT_VERIFIED`로 기록하고, 나머지 독립적인 구현·시험은 계속 완료하라.

**v2.2 통합 지시:** 현재 로컬의 회화 구현이 이미 진행 중이라면 그 변경을 보존하고 중단 없이 이어서 보드 갱신을 추가한다. 별도의 보드 개발 브랜치/두 번째 AI 구현자와 동시 편집으로 같은 파일을 충돌시키지 않는다. 같은 검사에서 이미 PASS한 범위는 근거를 재사용한다.

**필수 협업 방식:** 코드 구현과 독립 검토를 분리한다. 사용자는 작업 결과를 ChatGPT에 붙여넣어 독립 검토를 요청할 예정이다. 가능하면 현재 시스템에서 사용할 수 있는 **다른 리뷰 AI(예: Claude)를 읽기 전용**으로 활용하되, 불가능하면 `EXTERNAL_REVIEW_PENDING`이라고 보고하라. 자신이 구현한 코드를 자신이 읽는 검토는 독립 검토라고 표시하지 말라.

## 1. 절대 바꾸면 안 되는 사용자 의도

1. 원래 앱을 갈아엎지 않는다. 현행 **TOEIC / 해사영어 / 해사 통신 / 일본어 / 내가 만드는 문제집 / 오답노트 / 랭킹 / 출석 / 오프라인 PWA** 기능과 사용자 데이터를 보존한다.
2. 사용자가 선택한 것은 **옵션 2 = 구글 Gemini 무료 API**다. Workers AI 등으로 기본 엔진을 임의 교체하거나 무료 한도 소진 시 유료 또는 다른 API로 몰래 넘어가지 않는다.
3. 목표는 '챗봇'이 아닌 **진짜 회화 학습 프로그램**이다. **입문·초급·중급·고급 4단계 × 8단원 × 4차시 = 128차시** 구조를 구현한다. 이번 패키지는 **전체 128과의 데이터 계약·진도 구조 + 각 단계 앞의 2개 단원씩 32차시의 내용 초안 및 기능 구현**을 우선한다. AI 생성 콘텐츠를 사람 교사의 검수를 마쳤다고 보고하지 않는다.
4. **기존 앱 껍데기를 유지하되 모듈 등록·학습 콘텐츠 확장이 쉬워지는 최소 구조 개선**을 포함한다. 거대한 범용 플러그인 프레임워크, 리라이트, 필요 없는 UI 재설계 금지.
5. 교정은 사용자 의도·맥락·학습 목표를 구별한다. `Six.`, `Good.`, `Coffee, please.`와 같은 유효한 단답을 무조건 문법 오류로 판정하면 안 된다. **오류 교정 / 선택적 문장 확장 / 전사 불확실성**을 서로 다른 상태로 관리한다.
6. 기존 개인정보·문서·시험기록을 구글에 일괄 전송하지 않는다. 사용자가 별도 동의한 현재 회화 발화의 최소 정보만 서버를 통해 전달한다. Google 무료 등급은 입력·출력이 제품 개선에 사용되거나 사람 검토 대상이 될 수 있으므로 민감정보 금지 안내를 둔다.

**우선 보안 관찰:** 서버 `functions/api/[[route]].ts`의 `/api/admin/cleanup`은 정적 코드에서 접근 제어 없이 `performDatabaseCleanup()`과 삭제 SQL이 연결되어 보인다. **실서비스 URL에 해당 경로를 요청하거나 삭제 SQL을 운영에서 실행하지 말라.** 로컬 정적 분석 및 격리된 모의 DB 테스트로만 재현하고, 보호되지 않은 경우 **기본 차단(fail-closed)** 하는 최소한의 로컬 코드 보완과 회귀시험을 수행하라. 운영 적용은 승인 대상이다.

기준 시험은 수정 전 `npm run typecheck`, `npm test`, `npm run build`를 가능한 범위에서 실행하고 결과·기존 실패를 구분해 기록한다. 이미 작업 트리가 변경되어 있거나 사전 실패가 존재하면 소유권을 구별한다.

## 4. 교육과정은 실제 수업 내용으로 만든다

### 4.1 128차시 골격 + 첫 32차시

- 4단계 × 8단원 × 4차시. 각 단계 1~2단원은 **실제 32차시 콘텐츠 초안**을 작성한다. 각 차시는 내용 없는 제목/플레이스홀더가 아니라 목표·대표 문장·허용 답변·예시 대화·힌트·새 상황 평가·복습 태그를 포함한다.
- 단계마다 난이도 상승이 보여야 한다: 입문(인사, 자기소개), 초급(카페/식당, 길 찾기), 중급(과거 경험, 계획 변경), 고급(발표 구조화, 설득·논증). 다른 단원은 전체 128과 탐색 구조에 '콘텐츠 준비중'으로 표시하고 학습 완료로 표시하지 않는다.
- 각 단원의 4차시 표준 흐름: **① 이해·듣기 ② 문장 구성·자기수정 ③ 역할극 ④ 새로운 상황에서 평가**.
- 초기 32차시는 작성·스키마 검증·자동교육 테스트가 완료되어도 **`HUMAN_CURRICULUM_REVIEW_PENDING`**으로 표기. 사용자가 보거나 사람 교사가 확인하기 전 교육 최종 PASS 금지.
- 각 차시에 예시 응답을 여러 개 허용하고, 의미가 전달된 단답·불완전 문장·문법 오류를 구별하는 규칙을 정의한다. 자의적인 CEFR 공인 인증·학습효과 보장 금지.

### 4.2 튜터 동작 필수 순서

`상황 소개 → 핵심 표현 듣기 → 사용자 음성/텍스트 대답 → 의미 우선 평가 → (필요할 때만) 원포인트 교정 → 사용자의 수정 기회 → AI 다음 질문 → 수업 목표별 성취 판단 → 복습 예약`.

특히 아래 예시는 **절대 실패해서는 안 되는 골든 케이스**다.

| 맥락 | 학습자 답변 | 교정 분류와 올바른 동작 |
|---|---|---|
| “How old are you?” | “Six.” | `OPTIONAL_EXPANSION` 또는 `ACCEPT`; 틀린 문법이라고 단정 금지 |
| “How are you?” | “Good, thanks.” | `ACCEPT`; 불필요한 완전 문장 강요 금지 |
| 카페 주문 | “Coffee, please.” | `ACCEPT` 또는 목표에 따른 `OPTIONAL_EXPANSION`; 주문 실패 단정 금지 |
| 어제 무슨 일? | “I go there yesterday.” | `ERROR_CORRECTION`; 'went'가 핵심, 먼저 스스로 수정 유도 |
| “Two iced Americanos” 이미 주문됨 | 다음 AI 응답 | 뜨거운지 아이스인지 재질문 금지; 수량·주문 사실 유지 |
| 부정형·숫자가 음성 인식에서 애매 | 자동 전사 | `TRANSCRIPT_UNCERTAIN`; 말한 문장 확인 기회, 불확실한 상태에서 감점 금지 |
| “I don't know” | 대답 못함 | `NEEDS_HINT`; 단어 힌트→문장 틀→예문 제시 |

수업 합격과 복습 일정은 앱의 **규칙 엔진**이 최종 결정한다. LLM이 `MASTERED`라고 말했다는 이유만으로 기록 저장 금지. 객관적으로 검사할 수 없는 주관적 CEFR 인증 점수 금지.

## 5. AI API 계약 — 무료 Gemini만, 1턴 1회

### 5.1 공식 모델 식별자

| 용도 | 지정 모델 | 호출 게이트 |
|---|---|---|
| 대화 이해·교정·질문 | `gemini-3.8-flash` | Google 공식 구조화 응답/무료 등급 확인 |
| 음성→텍스트 | `gemini-3.5-transcribe` | **`verbatim`** 전사, 학생 원 발화를 깨끗하게 고쳐버리는 `smart` 금지 |
| 문장 TTS | `gemini-3.8-flash-lite-tts` | 공식 TTS API; 브라우저 TTS는 대체 재생기 |
| 음성 품질 비교 | `gemini-3.8-flash-tts` | 무료 프로젝트에서 접근·한도 확인 시에만 |
| 실시간 자유회화 | `gemini-3.8-live` | **이번 1차 패키지에서는 구조·향후 슬롯만, 실제 Live 연동은 제외** |

**중요:** '무료 등급'은 '모든 계정에서 언제나 무료 호출을 보장'한다는 의미가 아니다. Google AI Studio에서 프로젝트의 모델별 RPM/TPM/RPD·청구 연결 상태 확인 전 실제 API 연동 대량 시험·공개 배포 불허. 청구 프로젝트 여부가 불확실하면 **실제 호출은 하지 않고 모의 API로 완성·시험**한다. `gemini-4-argon` 등 무료 등급이 없는 모델 사용 금지. 모델명·SDK 인터페이스는 공식 문서 기준 검증하며 구형 1.5/2.0 모델 사용 금지.

### 5.2 JSON 및 한 턴 호출

앱은 **정적 수업 목표/장소·역할·사실 + 마지막 몇 턴 + 최소 사용자 텍스트**만 서버에 보내고, Gemini에는 단일 구조화 요청으로 `의미 평가 / 핵심 오류 0~1개 / 선택적 문장 확장 / 한국어 설명 / 영어 튜터 반응 / 다음 질문 / 힌트 / 추천 다음 학습 동작`을 반환받는다.

필수 Enum은 `ACCEPT | OPTIONAL_EXPANSION | ERROR_CORRECTION | TRANSCRIPT_UNCERTAIN | NEEDS_HINT | OFF_TOPIC`. 수업이 요구하지 않으면 교정 없이 다음 질문으로 넘어간다. **모델 출력은 서버에서 JSON Schema/런타임 유효성 검증 후 안전한 텍스트로만 렌더링**한다. 클라이언트에서 받은 수업 목표·시나리오를 믿지 말고 서버가 승인한 콘텐츠에서 조회. 응답의 HTML/JS는 렌더링 금지. `requestId` 중복/동시 클릭/중단 처리로 중복 소진 방지.

**권장 초기 제한(기술 설계 제안, Google 공식 한도 아님):** 텍스트 500자, 최근 대화 6~8턴, 응답 길이 제한, 오디오 30초·2MiB 이하, 요청당 최대 1회 자동 재시도(안전한 경우만), 클라이언트의 중복 전송 차단. 실측 후 고정값 조절.

### 5.3 키와 접근 제어

`GEMINI_API_KEY`는 서버 Secret만 허용. `VITE_*`, 클라이언트 JS, Git, 사용자 로컬 설정, URL query string, 로그에 삽입 금지. **요청자 인증·인가 없는 공개 Gemini 프록시 절대 금지.** 기존 기기 코드만으로 강한 인증이 되는 것은 아니며 CORS나 Origin 검사만으로 충분하지 않다. 비공개/제한된 내부 테스트 경로로 **기본 비활성화(fail closed)**하고, 실제 공개 기능 전환은 별도 승인.

Cloudflare 리소스가 허용된다면 D1 등에 원자적인 세션별/일일 제한·요청 중복 방지 메타정보를 설계하되, **운영 DB 마이그레이션은 하지 않는다.** 실사용량이 불명확하면 제한 설계를 과장해 `공개 안전 PASS`라 기록하지 말라. 개인정보가 포함된 AI 호출 원문은 서버 로그/DB에 저장하지 않는다.

## 6. 음성 인식·음성 재생

1. 사용자가 버튼을 눌러야 마이크 권한을 요청한다. 권한 거부·마이크 없음·iOS/Android 지원차가 있을 때 **텍스트 모드로 수업을 완주**할 수 있어야 한다.
2. 원음을 무단 장기 저장하거나 서버에 보관하지 않는다. 전사 요청 전 외부 전송 동의를 확인하고, 전사 텍스트를 **사용자가 확인·수정할 수 있게** 한다. 전사 오류를 학습자의 문법 오류로 계산하지 않는다.
3. 공식 `gemini-3.5-transcribe`은 현재 Interactions API 가이드의 **`verbatim`** 모드 사용. 현행 공식 파일 업로드/직접 입력 규격과 Cloudflare Workers 런타임 적합성을 확인하고 구현한다. 임의로 사용 안 되는 레거시 REST 형식을 가정하지 않는다.
4. TTS는 공식 `gemini-3.8-flash-lite-tts`로 출력. 브라우저 `speechSynthesis`가 실제로 잘 동작할 때만 폴백으로 사용. 기존 `/api/tts` 비공식 Translate 프록시는 기존 퀴즈에서 사용하더라도 새 AI 회화 모듈에서 **의존하지 않는다**.
5. 자동 재생 차단, 재생 중단·재시도, 같은 문장의 합법적 로컬 캐시, 429·네트워크 실패를 검증. **TTS 실패를 성공으로 포장 금지.** 발음 점수는 STT 인식값만으로 부여하지 않는다.

## 7. 데이터·진도·복습·백업

- `src/storage/db.ts`: 기존 Dexie v1/v2 데이터를 **추가형 v3 스키마**로 보존. 회화 진행·세션·교정/오답 복습·설정을 독립 저장. 원본 녹음 파일은 기본 미저장.
- `src/storage/backupService.ts`: 기존 백업 v1 **읽기 호환**을 유지하면서 신규 백업 형식 v2에 기존 `questionBooks`, `questions`, `questionStudyHistory`, `questionStats`, `sourceImages` 등 **기존 DB v2 전체와 신규 회화 테이블**을 포함. 필요시 로컬스토리지의 사용자 관찰 가능한 복습 정보를 안전하게 분리 포함하되 API 키·비밀번호·민감식별자 무단 포함 금지.
- **기존 v1 백업에 원래 포함되지 않았던 내용을 복원했다고 주장하지 말 것.** merge/중복키/충돌·이전 파일 읽기·손상 파일 거부를 검증하라. `replace` 경로를 실사용자 데이터에 적용하거나 운영 DB 초기화 금지.
- 복습은 `다음날 → 3일 → 7일 → 14일`을 시작값으로 사용하되 성취에 따른 조정이 가능하게 한다. 정답을 바로 보여주기보다는 **새로운 상황에서 회상 발화**시킨다.
- 진도 이어하기, 수업 중단·앱 종료 후 재진입, 기기별 로컬 저장을 확인한다. 기존 랭킹 점수(+10/-2)에 회화 결과를 자동 합산하지 않는다.

## 8. 기능 화면과 오류 처리

최소한 **회화 홈 / 수준·단원·수업 목록 / 개별 수업 / 상황극 / 학습 결과 / 회화 복습** 6개 기능 화면을 구현한다. 기존 테마·모바일 반응형 스타일·뒤로가기와 같은 패턴으로 구성하라. 128과 중 내용 미제작 차시는 진입하지 못하게 구분 표시. 첫 32차시의 강의/역할극/복습 흐름은 텍스트 모드로 **AI 없이도 로컬 교재 탐색·고정 과제 수행 가능**해야 한다.

오프라인 또는 무료 API 제한 시 `AI 생성 대화 일시 사용 불가`라고 정확히 안내하고 저장된 고정 수업·복습으로 전환. **모의 응답이나 미리 작성된 대본을 실제 Google AI 응답으로 위장 금지.** 400·401·403·429·5xx·timeout·불완전 JSON·빈 오디오·중복 클릭·네트워크 끊김 별도의 안전 UI 처리.

설계 기준은 **27개 신규 노드**로, 첨부본과 동일한 시작점이라면 전체는 **18탭·125노드**다. 이것은 신규 기능 구현을 통한 *목표 수치*이며, 로컬에 더 최신 개발이 있으면 현재 실측을 따르라. 기존 `NODE-xx`, `NODE-58B` 등의 ID를 덮어쓰지 말고 `CONV-xx` 네임스페이스를 사용하라. 새 탭·노드 이름, 상세 역할, 전제 관계, 오류·복구 분기는 **부록 D/E**를 따른다.

기존 알고리즘 보드가 단순한 카드 목록만 보여주더라도 이번 갱신에서는 **각 단계의 실제 연결 관계**를 추가한다. 기존 전체 아키텍처와 신규 회화 경로가 분리되면서도 연결되게 표시하라. 모든 화살표는 실제 있는 노드 ID를 가리켜야 하고 **정상 경로 / 음성 권한 거부 / 전사 오류 / API 한도·장애 / 유효한 단답 / 문법 수정 / 저장 실패 / 복습 / 출시 차단**이 추적 가능해야 한다.

### 11.3 카드 상세 15항목과 상태·근거

신규 카드에는 `역할`, `기술/스킬`, `입력`, `처리/분기`, `출력`, `실패 시 처리`, `상태 읽기`, `상태 저장`, `출처`, `파일`, `함수`, `관련 테스트`, `실행 근거`, `확인 수준`, `위험도` **15개**를 누락 없이 기록하라.

- 새 소스나 테스트가 실제 아직 작성되지 않았다면 `미구현/미작성/미검증` 표시. 미래의 파일명을 이미 존재하는 것으로 기록하지 말라.
- 개발 중 작성된 코드만 있다면 `코드로 확인`, 자동시험을 실행하고 통과했다면 별도 `자동시험으로 확인`, 실제 계정·실기기만 실제 검증으로 분류.
- 보드에 표시된 `P0`는 잠재적 위험 심각도이고, 확인된 실제 P0 결함이라는 뜻이 아님을 구분.
- 32차시 콘텐츠 사람 검토는 `사람 검수 대기`, 전체 128차시는 `데이터 틀 준비/실제 내용 검수 여부`를 분리.
- `CONV-27` Gemini Live는 **설계 단계**로 고정. 코드 없는 기능을 활성으로 표시하거나 완료 숫자에 포함하지 말 것.
- 회화 비동의/약관 미확인/비밀키 미연결/무료 한도 미확인 시 공개 API 기능은 차단되었다고 명확히 표현.

## 12. 보드 HTML/MD 단일 원천·사용성·검증

### 12.1 기존 사용성을 파괴하지 말 것

기존 어두운 디자인, 한국어 카드 제목, 탭, 실시간 검색, 범주 필터, P0/P1/P2 필터, 상세 드로어를 유지한다. 전체 구조에 회화 교육 경로를 추가하고 노드 클릭으로 상·하위 경로를 탐색할 수 있게 한다. 모바일 좁은 폭에서 화살표와 노드가 잘리거나 클릭 불가가 되지 않아야 한다. 키보드 탐색/ESC/닫기 버튼 동작도 보존한다.

**의미 있는 알고리즘 보드 조건:** 단지 신규 카드 27장을 추가하고 끝나는 것이 아니라, **사용자 입력 → 인식 → 판단 → 교육적 피드백 → 저장 → 복습**의 연결선·분기 조건·오류 대체 경로를 한눈에 추적할 수 있어야 한다. SVG 또는 CSS 연결 + 텍스트 경로 목록을 함께 제공하여 화면에서 보이지 않는 연결도 독자가 확인할 수 있게 한다. 외부 CDN 설치 강요 금지.

### 12.2 데이터 일치와 유지보수

- **권장:** `docs/algorithm-board/` 아래 단일 노드·탭·간선 데이터(`TABS/NODES/EDGES` 또는 동등한 스키마)를 두고 HTML과 MD를 결정론적으로 생성.
- 기존 MD에 단순 `NODES`에서 재생성하기 어려운 특별한 설명이 있으면 보존 규칙을 세워 내용 소실 검사를 먼저 작성한다. 본문 무손실 마이그레이션이 위험하면 보조 일치 검증 스크립트부터 구축하고 **두 파일을 증분 변경**하라.
- HTML과 MD는 모든 기존·신규 노드의 ID, 제목, 탭, 상태, 위험도, 설명, 상세 15항목, 관련 테스트, 간선 관계와 조건이 동일해야 한다.
- 헤더 노드/탭/P0 숫자는 실제 데이터 계산으로 표시(수동 상수 95 금지). 검색 결과 숫자, 카드 수 등과 상호 점검한다.
- 파일·함수·시험 링크는 실제 경로에만 연결. 누락 증거는 미검증 처리하며 과거 역사적 정보는 삭제 없이 별도 표기.
- `docs/범용 시각형 알고리즘 보드 지시서.md`의 한글 우선 규칙을 준수하여 **일반 영어만 있는 탭명/상태/상세 라벨 0개**를 유지하라.

### 12.3 최종 보드 파일
