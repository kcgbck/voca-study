- 원본과 개선 결과의 파일별 SHA-256, 기존 노드 ID의 보존 목록, 변경 사유를 남긴다.
- 사용자 표시 언어는 한국어 우선. **기존 `docs/범용 시각형 알고리즘 보드 지시서.md` 규칙이 우선**한다.
- 가능하면 `docs/algorithm-board/` 아래 JSON 또는 TS의 한 데이터셋(`tabs/nodes/edges`)을 단일 진실 공급원으로 삼아 HTML과 MD를 생성한다. 기존 수기 MD의 문장·이력·부연 설명을 지우지 않도록 마이그레이션 검사한다. 위험하다면 두 파일을 그대로 확장하면서 동치 검증 스크립트를 필수로 둔다.

`역할 / 기술·스킬 / 입력 / 처리·분기 / 출력 / 실패 시 처리 / 상태 읽기 / 상태 저장 / 출처 / 파일 / 함수 / 관련 테스트 / 실행 근거 / 확인 수준 / 위험도`

## E. 필수 연결 간선 계약 — 방향·분기·유형·실패처리

아래 관계를 기반으로 구현한 실제 흐름에 맞게 수정하되, 대상 노드 ID를 검증한다. 간선은 `{id, from, to, type, condition, summary}` 형태의 정형 자료로 관리할 것을 권장한다.

```text
[기존 셸] NODE-01 -> CONV-01 -> CONV-02 -> CONV-03 -> CONV-04 -> CONV-05
[텍스트 입력] CONV-05 -> CONV-13 -> CONV-21 -> CONV-22 -> CONV-23 -> CONV-14
[음성 입력] CONV-05 -> CONV-09 -> CONV-10 -> CONV-11 -> CONV-12 -> CONV-13
[음성 거부] CONV-09 -(권한 거부)-> CONV-05 (텍스트 모드)
[음성 애매] CONV-12 -(확인/수정)-> CONV-05 또는 CONV-13
[응답 판단] CONV-14 -> CONV-15 -> CONV-06
[교정/힌트] CONV-06 -> CONV-07 -> CONV-05
[정상 답변] CONV-06 -> CONV-08 -> CONV-18 -> CONV-19 -> CONV-02
[AI 응답 음성] CONV-15 -> CONV-16 -> CONV-05
[무료 한도/오프라인] CONV-14 -(오류)-> CONV-17 -> CONV-05 (정적 학습)
[녹음/전사 불가] CONV-11 -(오류)-> CONV-17
[백업] CONV-18 -> CONV-20
[검증] CONV-03 -> CONV-25; CONV-14 -> CONV-25; CONV-18 -> CONV-25
[운영 관문] CONV-24 -> CONV-26; CONV-25 -> CONV-26
[기존 기능 결합] NODE-49 -> CONV-18; NODE-58B -> CONV-17; NODE-96 -> CONV-21
[기존 인증과 구별] NODE-91 -> CONV-21 (기기 코드 ≠ 충분한 인증)
[과거 QA 보존] NODE-65 -> CONV-25; NODE-66 -> CONV-25; NODE-67 -> CONV-25
[향후 Live] CONV-27 -(설계 전용, 실제 작동 간선 금지)-> CONV-14
```

- 간선은 최소 **정상 경로, STT 거부/오인식, 무료 한도 초과, 서버 오류, 오프라인 대체, 중단·재개, 로컬 저장·복구**를 포함한다.
- `from/to`는 모두 존재하는 노드여야 한다. 마이그레이션 후도 기존 모든 ID의 유일성이 유지되어야 한다.
- `type`은 사용자/데이터/조건/성공/오류/복구/검증 등의 한글 표시를 지원한다.
- **화면에는 실제 간선이 읽히는 도식과 텍스트 대체 목록이 모두 존재**해야 한다. 단순 카드 나열을 전체 경로 시각화로 오인 금지.

## F. 시각형 보드 보강 동작 정의

1. 기존 다크 테마·검색·범주별 필터·위험도 필터·탭·카드 상세 드로어 유지.
2. 전체 흐름에 `AI 회화` 실행 경로를 추가하고, 시각적 연결선/화살표 또는 동등한 상호작용형 단계 연결을 제공. 모바일은 가로 스크롤/세로 단계별 보기로 탐색 가능해야 한다.
3. 노드 클릭 후 상세 15항목, 근거 파일/함수/시험, 현재 상태, 연관 상·하위 노드 이동 제공. `ESC`, 닫기, 포커스, 키보드 접근성 보존.
4. 헤더의 탭/노드/P0/확인등급/게이트 수는 데이터에서 산출. **상태 ‘작동 중’은 코드 존재만으로 붙이지 말고 실제 근거 수준을 함께 표시**한다.
5. HTML과 MD의 노드 ID·제목·탭·상태·위험도·상세 15항목·관련 테스트·간선 수/방향/조건이 일치해야 한다. 표현 방법 차이는 허용하되 의미 손실 금지.
6. 기술명이나 고유 API/파일명은 그대로 허용하지만 일반 표시 언어·상태 배지는 한국어. 사용자에게 예전 배포 도메인이 활성이라고 안내하지 말 것.
7. 노드 신설과 변경은 증분 병합. OCR/시험 등 AI 회화와 무관한 PASS 범위는 재검증 근거 없이 재판정하거나 삭제하지 말 것.
8. 자동 생성 스크립트는 같은 입력에서 같은 결과를 내야 한다. 두 번 생성해 diff가 0인지 검사한다.

## G. 보드 보강 검증과 완료 관문

**필수 자동시험(숫자는 요구사항, 실제 통과 실적 아님):**

- `BOARD-01` 첨부본/로컬본/변경본 비교 및 원본 식별자 보존, 누락 0건.
- `BOARD-02` 노드/탭/간선 ID 각각 고유, 참조 무결성 오류 0건.
- `BOARD-03` 신규 27개 노드 전부 실제 상태·파일·테스트·15항목 누락 0건(미구현은 명시 가능).
- `BOARD-04` HTML⇔MD 동일 노드·상태·위험·간선 내용 정합, 비교 오류 0건.
- `BOARD-05` 헤더 총계·필터별 건수·카드 건수 일치.
- `BOARD-06` HTML 검색·탭·위험도 필터·드로어·노드 이동·경로 도식·키보드 동작 테스트.
- `BOARD-07` 정상·오류·복구·오프라인·중단·보안차단 경로별 실재, 유실된 필수 경로 0건.
- `BOARD-08` 17개 기존 배지/확인 수준 의미 충돌 재검토 및 근거 기록(무근거 자동 PASS 금지).
- `BOARD-09` 실제 로컬 코드 파일 경로·테스트명 점검, 미존재 참조는 정확히 `미구현` 또는 `미확인`.
- `BOARD-10` 신규 모델/API/무료 한도/키 동의·로그 노출 관련 위험 노드가 해당 코드·시험 근거와 일치.
- `BOARD-11` 기존 보드의 15개 탭과 98개 노드(또는 더 최신의 로컬 기준선) 보존, 기존 데이터/기능 회귀.
- `BOARD-12` 정적 HTML 단독 브라우저 표시/작동 및 MD 열람; 실제 브라우저·기기 미검증이면 `미검증`.

**결과 상태:** `BOARD_STATUS = PASS | PASS_WITH_LIMITATIONS | FAIL`를 실제 자동/수동 근거에 따라 판단. 교육 32과 사람 검수, Gemini 실제 무료 계정 통신, 운영 배포가 보류면 보드에도 동일하게 보류 표기. 단순 문서가 존재하는 것만으로 PASS 금지.
