## 운영 방식

- 주소는 **https://voca-study-akf.pages.dev/** 하나만 사용한다. 설치된 PWA와 Chrome 모두 메인 홈의 **AI 영어 회화**에서 학습한다.
- 별도 `voice-check` React 진입점을 제거하고 항상 App을 렌더링한다. 이전 `voice-check`, `speech-check`, `build` 쿼리는 페이지 리로드 없이 지운다. 일반 회귀시험 파일과 과거 개발 근거 문서는 보존한다.
- 기존 Pages 프로젝트는 direct-upload 방식이다. Git main 푸시와 운영 배포는 별도 단계이므로 앞으로 검증 → 전체 저장 → 커밋 → main 푸시 → 동일 코드 Pages 운영 배포 → 기본 주소 확인 순서로 진행한다.
- 사용자 요청한 과거 배포 정리는 새 main 동작 확인 후 수행한다. 실행 시점의 canonical deployment를 재확인하여 삭제에서 제외하고, 해당 프로젝트의 나머지 과거 배포만 제거한다. Git 개발 이력과 원본 소스는 보존한다. Cloudflare가 현재 배포에 자동 부여하는 식별 주소는 플랫폼 메타데이터이며 사용자에게 별도 시험 주소로 안내하지 않는다.

## 설치 앱 업데이트

- Manifest의 id/start_url은 기존처럼 `/`다. SW 캐시 v8, SW HTTP no-cache 및 `updateViaCache: none`으로 새 코드 확인을 돕는다.
- 페이지 로드, 화면 복귀, 온라인 복구 시 SW 업데이트를 확인한다. 학습 중 강제 페이지 리로드를 하지 않는다.
- 이미 켜져 있는 오래된 화면이 자동으로 새 JS로 바뀌는 것은 아니다. 이번 통합 후 기존 설치 앱은 온라인 상태에서 홈 상단 **새로고침(🔄)**을 한 번 누르거나 종료 후 다시 열어 최신 메인을 불러온다. 앱 삭제·데이터 초기화는 필요하지 않다.
- SW 업데이트는 앱 이름으로 관리되는 구버전 셸 캐시만 정리하며 IndexedDB/localStorage를 지우지 않는다. 현재 단어장 보존 여부를 모듈 분리만으로 단정하지 않고 데이터·통합 회귀시험으로 확인했다.
