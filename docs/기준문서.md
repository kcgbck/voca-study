# Codex–Gemini 협업 기준

- 감독·검증: Codex. 구현: agy의 Gemini. 결정권자: 사용자.
- 작업 흐름: `Codex_Gemini_협업_개발_안내.md`의 계획 → 검토 → 구현 → 직접 검증 → diff 검토.
- 프로젝트 규칙: 루트 `AGENTS.md`가 연결하는 관리/프로젝트 지침, `CHECKS.md`를 먼저 읽는다.
- 상태 참고: `docs/partner/CURRENT.md`, `project_status.md`, `README.md`. 과거 상태가 서로 다르면 실제 코드와 검증 결과를 대조하고, 제품 방향 충돌은 사용자에게 확인한다.
- React + TypeScript + Vite PWA. 로컬 학습 데이터는 IndexedDB를 사용한다. 기존 서버 랭킹 구현과 신규 개인정보 전송 허용을 혼동하지 않는다.
- 사용자 사진·PDF·학습 기록 외부 전송 금지. 유료 종량제 API·API 키 추가 금지.
- 1,800단어 DB 동결 및 HUMAN_REVIEW_PENDING을 유지한다. 임의 출시 승인 금지.
- 한 번에 한 구현자만 파일을 수정한다. Gemini에게 정확한 입력 경로와 허용 수정 파일을 지정한다.
- 명시적 요청 없는 stage·commit·push·배포·DB 변경·설정 변경 금지.
- 검증: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1`. 기존 npm typecheck/lint/test/build와 보호 경로·diff 공백 검사를 실행한다.
- lint는 현재 타입 검사와 동일하며 별도 포맷 검사는 미설정이다. 브라우저 동작은 이 스크립트만으로 검증되지 않는다.
- 보호 경로 검사는 기존 변경도 포함한다. 보호 경로 작업이 승인된 경우 검사 우회 대신 허용 범위를 먼저 명시하고 검증 절차를 검토한다.
- 지시문/응답은 `.agy-work/`에 보관하며 민감 정보를 넣지 않는다. Git에서 로컬 제외한다.
