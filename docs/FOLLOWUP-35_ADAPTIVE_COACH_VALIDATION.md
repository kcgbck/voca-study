# FOLLOWUP-35: 상황 기반 회화 코치 — Codex 검증 및 개선 권고

검토일: 2026-10-24 / 기준 HEAD: `60c74754fe2d8d599619e3bfed4f4c813ff514ba`

## 결론

**무료 90% 제한을 유지하면서, 상황에 맞는 후속 질문과 답변 교정을 제공하는 방향은 가능하다.** 권장안은 서버에 준비한 초급 상황 질문 중에서 AI가 답변에 맞는 다음 질문을 고르고, 기존 답변 평가와 같은 호출에서 교정까지 반환하는 방식이다. Praktika와 같은 수준의 인식 정확도·자유 대화·응답 속도가 확보됐다는 뜻은 아니다.

Gemini 구독 CLI에 현재 개발 소스 기반 조사를 맡겼고, Codex가 소스·예산 SQL·기존 시험·직렬화 모의 실행으로 검토했다. Gemini 초안의 동시 사용자 수 보장, 근거 없는 평균 호출량, 예문을 학습자 정답처럼 재사용하는 표현은 채택하지 않았다. 이 문서가 검증 범위와 권고의 기준이며, Gemini 제안서는 설계 참고 자료다.

이번 작업은 조사·설계 검토다. 앱의 평가 API 추가 호출은 0회이며, 제품 코드·설정·DB·운영 배포를 변경하지 않았다. Gemini 구독 CLI의 조사 이용량은 앱의 무료 Gemini API 예산과 별개다.

## 현재 확인한 사실

- 현재 첫 답변과 달라진 반복 답변은 이미 `gemini-3.5-flash-lite`가 의미·완전한 문장 여부·한국어 조언·영어 예문을 평가한다. 자연어 평가 기능 자체가 없는 상태는 아니다.
- `COACH_QUESTIONS`는 이름·나이·카페·아침식사·취미의 고정 5문항이다. `CoachTutorView.tsx`의 `handleNextQuestion`은 인덱스를 증가시키며, 이전 답변 맥락을 서버 평가에 보내지 않는다. 상황이 이어지지 않는 주된 구조적 한계다.
- 기본 음성 입력은 Web Speech API, Whisper WASM은 비교 패널이다. 실제 S25 비교 결과는 아직 없으므로 Whisper 기본 적용 여부는 미결정이다.
- AI가 실제 학습자의 답변을 `relevant && sentenceComplete`로 승인한 경우에만 같은 질문의 동일 문장 반복을 재사용한다. 대소문자·공백·말미 종결부호 차이는 허용하지만 단어·숫자·부정어 변경은 평가 대상이다. STT의 다른 후보를 채택한 경우에는 잘못 인식된 원문을 승인 캐시에 넣지 않는다.

## 권장 학습 흐름

1. 초급 상황 하나를 고르면 준비한 첫 영어 질문을 제시한다. 첫 질문을 얻기 위한 별도 AI 호출은 없다.
2. 학습자의 새 답변에 대해 **의미 평가 + 한국어 원포인트 교정 + 영어 예문 + 다음 질문 선택**을 AI 1회에 요청한다.
3. 맞는 완전한 문장은 1회, 단답·교정이 필요한 답변은 2회 반복 연습한다. 처음 말한 교정 문장이나 달라진 답변은 AI로 평가하고, 이미 승인된 동일 문장 반복만 추가 호출 없이 처리한다.
4. 반복이 끝나고 사용자가 ‘다음’을 누르면 준비된 후속 질문으로 이동한다. 진행·피드백은 한국어, 질문·예문은 영어를 유지한다. 인식 확인 대화나 추가 로그인 절차는 넣지 않는다.

예시: 질문이 “What would you like to drink?”이고 답변이 “Coffee, please.”이면 “주문할 때 자연스럽게 쓸 수 있어요. 이번에는 ‘I would like coffee, please.’처럼 문장으로 연습해 볼게요.”라고 안내한다. 단답을 무조건 문법 오류로 취급하지 않는다. 반복 후 “Would you like that hot or iced?”로 이어간다.

첫 답변이 “I would like an iced tea, please.”이면 이미 온도를 말했으므로 사이즈 질문으로 건너뛴다. 커피로 메뉴를 바꾸거나 한국 이름을 Alex로 바꾸는 식의 추측 보정은 허용하지 않는다. STT가 coffee를 cup으로만 제공했다면 텍스트 평가 AI가 원래 음성을 들었다고 간주할 수 없다.

## 한도와 호출량 검증

아래 값은 사용자가 제공한 프로젝트 한도와 현재 코드의 설정이다. 현재 AI Studio 계정의 한도를 새로 조회한 결과나 모든 무료 계정에 공통인 수치는 아니다.

| 대화 모델 제한 | 프로젝트 제공값 | 앱에서 유지할 상한 |
| --- | ---: | ---: |
| 분당 요청 | 15 | 13 |
| 분당 입력 토큰 / 로컬 예약 계량 | 250,000 토큰 | 225,000 보수 예약 유닛 |
| 일일 요청 | 500 | 450개의 예산 평가 시도 |

로컬 예약 유닛은 실제 Google 토큰 계측값이 아니다. 90% 정책을 유지하려면 새 맥락을 계량에서 누락하지 않고, 기존 16,384 기본 예약을 임의로 낮추지 않아야 한다. D1은 `reserved`·`consumed` 상태를 집계한다. consume 후 실제 fetch 전에 취소되는 경우도 있어 450은 제공사 도달 횟수나 완료 문항 수와 정확히 같지 않다. 외부 실패·시간 초과도 소모될 수 있다.

현재 핸들러에 합성 문장 `I would like tea, please.`를 넣고 제공사 응답만 모의한 결과:

- HTTP 200 / 모의 제공사 호출 1회 / 외부 네트워크 호출 0회.
- D1 예약·소모 16,486 유닛, 제공사 요청 JSON 3,314 UTF-8 바이트, 출력 상한 512 토큰.
- 여기에 계량되는 맥락이 1,024바이트 늘어난다고 가정하면 17,510유닛이며, `floor(225000 / 17510) = 12`라서 분당 13회보다 TPM 제한이 먼저 작동할 수 있다. 이는 산술 가정이며 새 설계의 실측값이 아니다.

10문항을 전부 처음에 완전하게 답하고 동일 반복을 재사용하면 10회, 전부 단답 후 완전한 문장을 한 번씩 재평가하면 20회다. 실패·추가 오답·다른 이용자·기존 소모가 전혀 없다는 가정에서 하루 **45회 또는 22회의 10문항 수업**에 해당한다. 실제 수업당 최대 20회가 보장되는 것은 아니다. 계속 답변이 달라지면 더 소모한다.

사용자당 분당 제한은 `min(실제 설정값, 13)`을 유지한다. 전체 요청 수와 전체 예약 유닛이 각각 제한을 만족해야 하므로 동시 이용 인원이나 무중단 사용을 보장하지 않는다. 개인 학습에 먼저 검증할 만한 규모이나, 다수 공개 사용의 충분한 용량이라는 근거는 없다.

Google 공식 문서도 RPM·입력 TPM·RPD를 각각 적용하고, 키별이 아닌 프로젝트별 제한이며 실제 처리 용량은 보장되지 않는다고 설명한다. 같은 Google 프로젝트를 쓰는 다른 앱의 사용량은 우리 D1이 자동 합산하지 않는다. [Google 제한 안내](https://ai.google.dev/gemini-api/docs/rate-limits)

## 구현 시 지킬 경계

- 처음에는 **카페 주문 한 상황, 기본 6문항 / 온도를 먼저 답하면 5문항**만 구현한다. 음료 → 온도 → 크기 → 매장/포장 → 추가 옵션 → 결제 순서에서 허용된 건너뛰기만 사용한다.
- 서버가 현재 질문과 후속 후보 최대 3개의 ID·영어 질문·목표/선택 기준을 제공한다. AI는 그 안에서 고른다. 무제한 자유 생성이나 평가·질문별 다중 호출은 우선 도입하지 않는다.
- 최근 최대 2턴, 맥락 JSON 전체 1,024 UTF-8 바이트 이내, 요청 본문 4 KiB 제한을 목표로 한다. 넘으면 오래된 턴 전체를 버리며 실제 답변·이름·부정어를 잘라 바꾸지 않는다. 실제 직렬화된 전체 프롬프트·후보·스키마를 포함해 계량을 재검증한다.
- 클라이언트 맥락은 서식·길이·ID만 검증할 수 있고 과거 발화의 진실성까지 증명할 수 없다. 지시문이 아닌 불신 입력 데이터로 처리한다.
- 응답의 후보 인덱스, 필드, 길이, 다음 질문의 허용 간선을 서버와 클라이언트에서 검증한다. 마지막 질문에서만 완료 sentinel을 허용한다. 유효하지 않은 추천은 이미 소모된 평가의 오류로 처리하고 현재 단계를 유지하며 자동 재시도·임의 성공·자동 전이를 하지 않는다.
- 다음 질문은 반복 완료까지 보류하고, 새 질문 인스턴스로 이동하면 승인 캐시를 초기화한다. “Yes, please.”가 이전 질문에서 맞았다는 이유로 새 질문까지 자동 정답 처리하지 않는다.
- AI 예문 자체는 승인된 학습자 답변이 아니다. 예문을 듣고 따라하는 무채점 복습과, 실제 답변을 승인한 뒤 동일 반복을 정답으로 재사용하는 기능을 구분한다.
- JSON 구조를 맞추는 것과 교육적으로 올바른 판단은 다르다. 스키마만으로 정답·문맥·길이를 보장하지 않는다. [Google 구조화 응답 안내](https://ai.google.dev/gemini-api/docs/structured-output)

변경 대상은 `coachProtocol.ts`, `publicCoachHandler.ts`, `publicCoachApi.ts`, `CoachTutorController.ts`, `CoachTutorView.tsx` 및 관련 시험으로 예상한다. 3개 파일로 제한하려고 요청·응답 검증이나 상태·캐시 수명 관리를 생략해서는 안 된다. 단어장 DB와 학습 기록 저장 구조를 바꿀 이유는 없다.
