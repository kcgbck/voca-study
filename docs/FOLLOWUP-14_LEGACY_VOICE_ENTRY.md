# FOLLOWUP-14 기존 음성 검사 주소의 학습 진입 오류

## 근거와 원인
- 사용자는 S25 Chrome에서 질문은 들리지만 인식이 부정확하고 안내·피드백이 영어라고 보고했다.
- 사용자에게 화면을 확인하자 `음성 연결 확인 / 확인 시작 / 음성 연결 v1`이라고 답했다.
- 운영 주소 `/?voice-check=1&build=20261023-2`를 직접 열어 같은 검사 화면을 재현했다.
- `src/main.tsx`가 voice-check=1이면 새 CoachTutorView 대신 기존 HandsFreeSpeechCheck를 계속 렌더링한다.
- 기존 검사는 영어 질문과 `I heard you say...` 읽기만 수행하며 실제 AI 평가·한국어 코칭을 하지 않는다. 새 배포를 새로고침해도 URL 쿼리가 남아 있으면 검사 화면이 계속 열린다.
- Codex가 추가한 진입 회귀 시험에서 기존 검사 주소는 새 코치를 렌더링하지 않아 실패했고, 정상 홈페이지 경로는 통과했다.

## 수정 범위와 검증 계획
- Gemini가 main.tsx의 기존 검사 주소 진입만 새 한국어 안내 코치로 연결한다. 기존 검사 소스·기록은 삭제하지 않는다.
- 정상 홈페이지, 공개 Access, 예산 90% 한도, API 키·DB·단어 데이터는 바꾸지 않는다.
- 진입 회귀 시험 → 전체 verify.ps1 → 기존 승인 범위의 교정 배포 → 같은 기존 URL을 다시 열어 새 화면 확인.
- 음성 인식 엔진 자체의 품질 결함으로 아직 단정하지 않는다. 새 흐름에서 생각 시간·한국어 안내·인식 문장 확인이 실제 S25에서 동작하는지는 별도 확인한다.

## 수정·배포 결과
- Gemini가 `src/main.tsx` 한 파일에서 기존 voice-check 진입을 CoachTutorView로 교체하고 옛 검사 배지를 제거했다. 정상 루트 App은 그대로 유지했다.
- `scripts/verify.ps1` exit 0: 66개 파일/580개 시험, typecheck/lint/build/보호 경로/diff 검사 통과 (`.agy-work/096_legacy_entry_verify.log`).
- 회귀 시험은 기존 URL에서 CoachTutorView가 선택되고 퇴역 검사 컴포넌트가 선택되지 않음을 확인한다. 정상 루트의 App 진입도 통과한다.
- 코치 첫 음성 호출이 상황 한국어/ko-KR, 두 번째가 영어 질문/en-US 순서임을 기존 컨트롤러 시험에 명시적으로 확인했다.
- 제공된 비밀키 문자열의 소스·문서·빌드 노출 검사: 253개 파일, 매칭 0.
- 교정 배포 완료: `50d68b69`, 기존 voca-study 운영 Direct Upload, Git commit/push 없음 (`.agy-work/097_legacy_entry_deploy.log`).
- 운영의 정확히 같은 `/?voice-check=1&build=20261023-2` 탭을 새로고침하여 ‘AI 영어 회화 (초급)’, 성인 체크 1개, ‘코칭 시작’을 확인했다. ‘음성 연결 v1/확인 시작’이 더 이상 나타나지 않는다 (`.agy-work/098_legacy_url_now_coach.png`).
- 이번 교정은 진입 경로만 바꿨고 음성 엔진·Access·예산·키·DB는 바꾸지 않았다. Google 모델을 추가 호출하지 않았다.
- S25에서 새 코치의 실제 한국어 음성과 정확한 인식 확인은 사용자 재시험을 요청했다. 이 결과 없이 음성 인식 품질 자체가 해결됐다고 표시하지 않는다.
